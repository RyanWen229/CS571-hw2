\section*{I. Supervised Entity Tagging}
\textbf{Task and protocol.}
I convert mention spans to token-level BIO tags over PER, ORG, LOC, TIME, NUM,
and MISC. A mention is correct only when document, sentence, start, end, and
type exactly match gold. All settings are selected on the 500-document dev
split; test is evaluated only after the NER and RE stages are locked.

\textbf{Classifier and hand-written feature set.}
The tagger is trained from scratch with scikit-learn: an averaged multiclass
\texttt{SGDClassifier} with one-vs-rest logistic loss over nonnegative
\texttt{FeatureHasher} columns. For token $w_i$, my feature function emits:
original and case-folded form; prefixes/suffixes of lengths 1--5; compressed
word shape; capped length; uppercase, title-case, lowercase, digit,
embedded-digit, hyphen, and alphanumeric flags; case-folded word and shape for
a $\pm3$ window; boundary symbols; left/right lexical bigrams; and the preceding
BIO tag (gold in training, hypothesized in decoding). No pretrained encoder,
pipeline, embedding, or external NER model is used.

\textbf{Training and decoding.}
The selected model has $2^{19}$ hashed dimensions, L2 $\alpha=10^{-6}$, at
most 20 epochs, tolerance $10^{-3}$, averaged weights, O-token weight .60, and
seed 571. A width-4 left-to-right beam uses class log probabilities and rejects
an I-X transition unless preceded by B-X or I-X; a final repair converts any
remaining orphan I-X to B-X. Longer gold spans win annotation overlaps.
Decoded mentions are grouped iff type and case-folded, whitespace-normalized
surface form match.

\section*{II. Relation Extraction}
\textbf{Two-stage protocol and entity construction.}
NER is selected and frozen on dev before RE selection. BIO segments become
mentions; equal type plus case-folded normalized surface form defines an entity
cluster and its \texttt{vertexSet} index. For $n$ entities, every ordered
$(h,t)$ with $h\ne t$ is a candidate, so direction is explicit. Self-pairs and
cross-document pairs are excluded.

\textbf{Feature set and classifier.}
For each pair, sparse categorical features encode head/tail types and their
order; normalized names, name tokens, and ordered name pair; mention-count
buckets; title occurrence; closest-mention sentence distance, same-sentence
status and argument order; token-distance bucket; up to 12 intervening tokens;
and immediate left/right argument context. They map to $2^{19}$ nonnegative
hashed dimensions. The classifier is averaged multiclass SGD with logistic
loss, L2 $\alpha=2\times10^{-6}$, 25 epochs, tolerance $10^{-3}$, and seed 571.
All positives are retained; unrelated pairs are sampled five per positive.
Class weight is $\min(8,(n_{\max}/n_y)^{0.2})$. The dev-selected multi-label
decoder emits at most two relations when $p(r)\ge .90p(\texttt{no\_relation})$.

\textbf{Output and evaluation.}
The predictor preserves sentences and predicted \texttt{vertexSet}, removes
input labels, and writes dictionaries \texttt{\{h,t,r\}}. Both final files
pass \texttt{check\_format.py --re} and \texttt{re\_eval.py}. Pipeline
evaluation aligns predicted to gold entities through exact shared spans;
triples with an unaligned endpoint are false positives.

\textbf{Error analysis and pipeline-versus-gold gap.}
Replacing predicted entities with gold raises test F1 from .3418 to .4732, a
.1314 gap. Predicted entities reach 90.1\% of gold entities and make 86.9\%
of gold triples reachable; 5,930 predicted triples have an unaligned endpoint.
Even with gold entities, 9,371 false negatives show that relation classification
is still a major bottleneck. Frequent geographic labels remain confusable,
while P527/P361 (has-part/part-of) suffer from direction and sparse evidence.
Relation-specific thresholds and entity confidence are the clearest next steps.

\section*{III. Extra Credit: Distant Supervision}
\textbf{Database and weak labels.}
I use Wikidata because DocRED's 96 predicates are Wikidata property IDs and
Wikidata represents item--property--value statements \cite{wikidata}.
Following DocRED \cite{docred}, mentions linked to the same KB item are merged
and item pairs receive their Wikidata properties. For reproducibility,
\texttt{prepare\_distant\_supervision.py} matches title plus complete tokenized
text to official \texttt{train\_distant.json}, rather than using changing live
queries. All 10,000 documents match, restoring 192,955 weak entity clusters
and 147,974 weak relation labels.

\textbf{NER use and dev selection.}
The final model keeps the same hand-written features and scikit-learn
classifier. It adds all weak entity tokens plus O tokens within two positions
of a weak mention; focused sampling avoids letting roughly two million weak O
tokens dominate. Weak examples receive source weight .50 versus 1.0 for human
examples. The weight was chosen on dev (.10, .20, .30, .50, .75 tried);
features, classifier, and decoder remain unchanged. Thus no pretrained model
is introduced.

\textbf{RE use and dev selection.}
All weak positive pairs and sampled negative pairs are included with source
weight .25. Human rows retain weight 1.0. The final decoder cap 2 and ratio
.90 are selected on full-pipeline dev after NER is frozen. Stronger weak weight
1.0 reduced dev F1 to .3291 and was rejected.

\textbf{Reproducibility and output QA.}
\texttt{make train-ner}, \texttt{make predict-ner SPLIT=dev}, and
\texttt{make eval-ner SPLIT=dev} are the one-command NER operations; RE has
parallel targets. Test replaces \texttt{dev} only after selection. The four
JSON files pass both format checks and evaluators. I opened the NER and RE test
outputs in the supplied annotation viewer; all 500 documents rendered with
populated BIO/entity and relation layers.
